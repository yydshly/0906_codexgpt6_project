# 引导式数字油画室：产品与 AI 开发任务包

版本：0.1 · 2026-09-05

这是一份待验证的产品定义与开发任务书，不是已经实现的应用，也不代表市场需求已经得到验证。
本包沿用“不会画画的人，也能亲手完成一幅值得保存的小画”作为验证方向。

## 如何开始

把整个 `oil-painting-product-kit` 文件夹放到你选定的项目根目录，保留目录名。不要直接覆盖仓库里已有的 AGENTS.md、代码或配置。

包内文件：

- PRODUCT.md：目标用户、核心场景、首版边界、后续扩展条件。
- EXPERIENCE.md：页面、交互、笔触、材质、数据与技术约束。
- ACCEPTANCE.md：功能、视觉、性能与用户验证标准。
- AGENTS.template.md：供合并进仓库 AGENTS.md 的执行约束，不应直接覆盖旧规则。
- reference/reference.png：用户提供的视觉参考截图，仅用来讨论材质、布局和氛围，不作为应用的运行界面或成品素材。

## 第一条指令：调查与计划，不开始全量开发

将下面内容交给 Codex：

```text
请读取 oil-painting-product-kit 下的 README.md、PRODUCT.md、EXPERIENCE.md、ACCEPTANCE.md、AGENTS.template.md，并查看 reference/reference.png。

目标不是复刻截图，也不是搭建专业绘画平台，而是做一个有油画质感、能真实绘制并完成作品的引导式数字画室。

本轮只执行 M0：
1. 调查当前仓库、既有 AGENTS.md、技术栈、启动方式、依赖和可复用能力；空仓库则明确说明。
2. 用一个具体的首次使用故事复述目标，不重新发明产品定位。
3. 给出最小主技术路线，区分页面视觉、绘画引擎、材质渲染与数据保存；不要把每次落笔交给大模型。
4. 列出实现最大风险，特别是笔触材质、混色、性能与撤销一致性。必要的验证必须有范围和退出条件。
5. 给出 M1 方案：同一个经过设计的页面里，真正完成取色、落笔、覆盖/基础混色、撤销和 PNG 导出。不能只做静态高保真页面，也不能交付无设计的普通画板。
6. 写出执行计划和验收命令；列出需要合并到现有 AGENTS.md 的规则差异。

本轮可以新增或更新计划文档，不修改业务代码、不安装大量依赖、不发布、不部署、不变更账号/收费服务。存在与已有约束的冲突时先报告。
完成后停止，等待我确认 M1 方案。
```

## 第二条指令：批准后执行 M1

```text
确认已讨论的 M1 方案。现在执行 M1，不扩展到 M2。

先按确认结果合并项目级执行约束，保留所有不冲突的既有规则。
实现高质感的最小完整切片：取色 → 连续真实绘制 → 覆盖/基础混色 → 撤销 → 导出真实 PNG。
同一页面必须同时具备视觉完成度和真实交互；不是先交付样子，再承诺以后补绘画。

优先攻克画笔落在画布上的效果。禁止用整张背景图片、预绘制作品揭幕或普通圆线条加页面阴影冒充核心能力。
不添加登录、支付、社区、任意照片 AI 转换或完整 3D 房间。

按 ACCEPTANCE.md 执行 M1 对应测试，实际运行页面，保存固定测试笔触的截图、端到端操作录像、导出 PNG 和测试结果。
报告运行方式、改动、已通过/未通过/未测项目、真实测试环境、已知问题。
若环境缺少浏览器或 GPU 验证能力，请明确标注，提供可复现的本机验证步骤，不虚构效果、帧率或完成状态。
遇到必须新增付费服务、改变核心渲染路线或重构无关模块的情况，先停下说明。
完成后停止，等待视觉与交互验收。
```

## 第三条指令：M1 合格后执行 M2

```text
M1 已通过验收。保留已经确认的视觉风格和绘画引擎，现在只执行 M2。

将“旅行日落”做成首个完整引导场景：开始体验 → 分步绘制 → 可关闭引导 → 撤销修正 → 本地保存/恢复 → 签名完成 → 导出。
只做一个经过设计的主题；不要扩成课程平台，不接任意照片分析、不接支付和社区。
指导内容与真实绘画数据分离。关闭引导后只剩用户实际画出的内容；导出不得包含参考图、辅助轮廓、工具栏或调试元素。
作品保存需要支持继续编辑，不得只有预览截图。

按 ACCEPTANCE.md 完成 M2 测试，补充截图和端到端录像，并提交一次用户测试说明。
不能因添加主题而破坏 M1 已通过的笔触、混色、撤销和导出行为。
完成后停止，不擅自进入商业化开发。
```

## 视觉不达标时的纠偏指令

```text
当前版本未通过视觉验收。这一轮不要添加功能，也不要重新设计产品。
请把参考图、当前页面和固定测试笔触截图并排检查，分别诊断：空间与布局、材料与光照、笔触方向与边缘、叠色与厚度。
用可观察的差异描述问题，不使用“再高级一点”“进一步优化”等笼统表述。
先给出最关键的三处差异及修复方案；按确认方案修改并重新运行相同笔触测试。
提交前后对比、真实操作录像以及剩余差异。不要通过更换测试样本、遮挡画布或修改验收口径来宣布通过。
```

## 里程碑与停止条件

M0：先调查与计划，用户确认后才改业务代码。
M1：高质感、可操作的最小闭环。不通过核心笔触验收，不继续做主题、账号、社交功能。
M2：一个新手可完成的完整体验。不能完成任务，先修路径和引导，不扩展内容库。
M3：邀请真实用户试用，决定继续引导创作、转向自由休闲，或停止当前方向。

M1 首个可运行版本之后，建议最多先做两轮聚焦的视觉修正，再重新评估路线、投入和效果差距；这是试验预算，不是对开发工期的承诺。
